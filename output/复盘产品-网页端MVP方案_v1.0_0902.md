## 1. 产品定位（继承 v0.2，不变）

### 1.1 核心主张

【原文】"复盘不是反思错误，而是发现自己早已拥有的财富。"

- 传统复盘 = **检讨式复盘**（只挑错、自我批判）→ 长期坚持导致自卑与抵触。
- 本书主张 = **发现式复盘**：痛苦、挫折、喜悦、困境中，都藏着你的优势、价值观、潜在能力，只是从未被梳理。

> 产品的全部价值主张、文案基调、功能引导，都必须围绕"发现式复盘"展开。这是产品的护城河，也是与市面上"反思找差距"类工具的根本区隔。

### 1.2 产品设计五原则（由书推导）

| # | 原则 | 本期落地方式 |
|---|---|---|
| 1 | **不批判** | 所有引导语、反馈文案只做"发现"，绝不做批评；删除/清空二次确认且语气温和，不用红色警示 |
| 2 | **低负担** | 单次 ≤5 分钟；输入即存草稿；八栏中仅 3 栏必填，不强求填满 |
| 3 | **有引导** | 八栏原文引导提问 + 情绪轮盘选词 + 切分实时提示，用户不空想 |
| 4 | **中断友好** | 断签不惩罚、不显示"已断签"；日历空白日期不加任何缺失标记 |
| 5 | **成长可见** | 日历色阶回看可视化记录连续性；保存后即时正反馈 |

## 3. 形态方案：单文件网页 + 本地存储 + GitHub 同步

### 3.1 为什么改网页端

| 对比 | 微信小程序 | 网页端（本期选择） |
|---|---|---|
| 前置步骤 | 注册小程序账号、主体认证、备案、类目审核、提审上线 | **无**，写完代码即可打开使用 |
| 触达能力 | 订阅消息（强） | 弱（无推送） |
| 分享能力 | 微信生态裂变（强） | 弱（链接分享） |
| 迭代速度 | 每次发版需审核 | **即时更新** |
| 数据私密性 | 上云 | **数据默认只在自己浏览器里**（隐私更强） |

**结论**：小程序的前置成本与"先验证方法论闭环"的当前目标不匹配。网页端以牺牲提醒/分享能力为代价，换取**零门槛、快迭代、强隐私**，更契合第一期"先验证写复盘这件事本身能否成立"。

### 3.2 技术组合（v1.1 调整）

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | **单文件 HTML**（HTML + CSS + JS 全内联） | 零依赖、零构建、双击即用；借鉴用户已有 todolist 的工程范式，**代码从零写，不复用** |
| 样式 | 内联 CSS + CSS 变量（设计令牌） | 支持明暗主题切换 |
| 存储 | **浏览器 localStorage（4 层 key）** | 主数据 / 自动备份 / 偏好设置 / 同步配置 |
| 云同步 | **GitHub Contents API**（GET 拉取 + PUT 回推） | 存储仓库中的一个 JSON 文件；启动时拉取、保存后回推；按 `date` 合并取较新 |
| 备份 | **JSON 导出 / 导入** | 应对清缓存、换设备 |

**为什么从 React + Vite 改为单文件 HTML**：本产品的使用者就是用户自己、数据只在本地、无需协作与工程化。用户已有的 todolist 产品（`todo.html` + `todo-data.json` + GitHub 同步）已验证这套范式可用且省心——**沿用范式，代码从零写**。代价是代码集中在单文件（约 1500 行），二期若要扩展再考虑拆分。

**对 todolist 范式做的 4 处改进**：

1. token 改为**设置页输入存本地**，不硬编码进文件（避免泄露）；
2. 输入时**不做全量重渲染**（避免光标丢失）；
3. Base64 编码用 `TextEncoder`，不用已废弃的 `unescape`（避免中文乱码）；
4. 全量 `escapeHtml` 转义用户输入（防注入）。

### 3.3 数据模型（v1.2 八栏 · 一天最多 3 条）

**一天最多记录 3 条**——同一天可能有多件触动自己的事，每一件都可以单独走完八栏。

```javascript
// 存储结构：以 date 为键，值为该天的条目数组（最多 3 条）
S.records = {
  "2026-09-02": [
    {
      id: "m1x2k3p",          // 条目唯一 id（合并/同步的主键）
      date: "2026-09-02",
      event: "",                 // ① 事件【必填】
      thoughts: "",              // ② 当时的想法和感受【必填】
      emotions: [],              // ② 的情绪标签（由情绪轮盘点选追加）
      action: "",                // ③ 行动
      result: "",                // ④ 结果
      reframe: "",               // ①-A 重新注意到了什么（意义重塑）【必填】
      nextAction: "",            // ② 从现在开始可以采取的行动
      expectResult: "",          // ③ 这些行动可能会带来怎样的结果
      selfDiscovery: "",         // ①-B 对自己的新发现
      isDraft: true,             // 草稿态，体现"中断友好"
      createdAt: 1756...,        // 时间戳
      updatedAt: 1756...         // 云同步合并时取较新
    }
    // …同一天最多 3 条
  ]
}
```

**存储 key**：

| key | 用途 |
|---|---|
| `review_records` | 主数据（以 date 为键、条目数组为值） |
| `review_backup` | 上一次的主数据快照（自动备份，导入/清空前留痕） |
| `review_pref` | 偏好设置（主题、是否展开轮盘等） |
| `review_sync` | GitHub 同步配置（token / 用户名 / 仓库 / 路径） |

**关键设计决策**：

1. 八栏字段以 **FIELDS 配置数组集中管理**（编号 / 键名 / 标题 / 引导语 / 必填 / 所属步骤 / 子问题）。字段再变只改配置、不动渲染与存储逻辑。
2. **同步主键从 `date` 改为 `id`**。一天一条时按 `date` 合并即可；改成一天多条后，按 `date` 合并会互相覆盖——必须按条目 `id` 匹配、取 `updatedAt` 较新。
3. **旧数据自动迁移**：早期版本 `records[date]` 是单个对象，加载时统一升级为数组（`toList` / `normalizeAll`），老用户无需手动处理。
4. **合并上限与新增上限分离**：新增受 3 条限制；但从云端/JSON 合并时**不截断**（若历史数据超过 3 条则全量保留），数据安全优先于展示约束。

### 3.4 本地存储的风险与应对（v1.1 更新）

| 风险 | 影响 | 应对 |
|---|---|---|
| 清浏览器缓存 / 无痕模式 | 数据全丢 | ①首次进入温和提示"数据保存在本机，建议开启 GitHub 同步或定期导出备份"；②设置页 JSON 导出/导入；③**开启云同步后风险归零** |
| 换设备 / 换浏览器 | 数据不跟随 | **已解决**：GitHub 云同步（GET 拉取 + PUT 回推，按 `date` 合并取较新） |
| 多标签页并发写入 | 覆盖冲突 | 读取时以 `date` 为主键合并；云同步冲突时按 `updatedAt` 取较新 |
| 云推送 sha 冲突（409） | 推送失败 | 自动"先拉再推"一次；非 409 错误不重试、不静默吞错 |
| 存储容量上限（约 5MB） | 纯文本记录可支撑数年 | 设置页显示已用容量；接近上限提示导出归档 |
| token 泄露 | 仓库被改 | token 存本地不进文件；同步仅操作指定路径的单个 JSON 文件 |

### 3.5 "无提醒"如何保证坚持

网页端没有可靠推送，但**不能让"坚持"完全依赖自律**。MVP 用三层替代机制：

1. **日历可视化的连续反馈**（主要手段）：日历页用色阶呈现记录密度，"看得见的连续"本身就是最强的回访动机，且完全不具惩罚性——空白日期不标记缺失。
2. **降低单次门槛**：5 分钟 + 输入即存草稿 + 仅 3 栏必填，让"今天太累"不再成为中断理由。
3. **回归不追问**：重新打开即回到首页，不弹"你已断签 N 天"之类的任何提示。

> 【AI提炼】这三层把"靠提醒坚持"转换为"靠可视化 + 低门槛坚持"，反而更贴合书中"中断也没关系，像健身一样屡败屡战"的主张。
> **注**：v1.0 计划的"浏览器通知提醒"本期**未实现**（通知授权本身即是一种打扰，与"不催促、不评判"冲突）。

### 4.2 F1 每日八栏记录（核心）【原文·已锁定】

**八栏模板**严格按书中"两步、左右两栏"排布：

#### 第一步（记录）· 左栏

| # | 编号 | 栏位 | 必填 | 引导提问（原文） | 配套机制 |
|---|---|---|---|---|---|
| 1 | ① | 事件 | ✅ | 什么事件让你内心有所触动？ | **切分检测**：命中主观词（我觉得/很糟糕/居然/太过分）→ 提示"这更像是感受，挪到②栏吧" |
| 2 | ② | 当时的想法和感受 | ✅ | 事件发生时，你的想法和感受是什么？ | 真心话原则提示 + **情绪轮盘**查阅面板 |
| 3 | ③ | 行动 | ⬜ | 当时你采取了什么行动？ | — |
| 4 | ④ | 结果 | ⬜ | 当时的行动带来了什么结果？ | — |

#### 第二步（意义重塑）· 右栏

| # | 编号 | 栏位 | 必填 | 引导提问（原文） | 配套机制 |
|---|---|---|---|---|---|
| 5 | ①-A | 重新注意到了什么 | ✅ | 回顾事件及左侧所写内容后，你重新注意到了什么？ | 顺序不可颠倒（ALACT：先理解本质，再找行动） |
| 6 | ② | 从现在开始可以采取的行动 | ⬜ | 从现在开始，你可以采取什么具体行动？ | **切分检测（第二处）**：命中"希望对方/取得信任/他应该"→ 提示改成"我计划…""我将尝试…" |
| 7 | ③ | 这些行动可能会带来怎样的结果 | ⬜ | 这些行动可能会带来怎样的结果？ | 提示"即使看似什么都没有发生，那也是结果的一种" |

#### 延伸 · 第二步末尾（不折叠）

| # | 编号 | 栏位 | 必填 | 引导提问（原文） |
|---|---|---|---|---|
| 8 | ①-B | 对自己的新发现 | ⬜ | 是否有对自己的新发现？<br>· 我的心中为什么会产生那样的想法？<br>· 那一刻，我真正渴望的是什么？<br>· 是否还存在其他可选方式？ |

**一天不限条数**：同一天若有多件触动自己的事，可逐条记录，每条独立走完八栏、独立保存、独立编辑与删除。**不设上限**——想记几条就记几条。

| 交互位置 | 表现 |
|---|---|
| 首页 | 显示"今天已经记下 N 条"；常驻"再记一条（第 N+1 条）" |
| 记录页 | 顶部条目指示"今天第 N 条 · 共 M 条"，多条时左右箭头切换；底部"完成，保存" + "保存，再记一条" |
| 正反馈页 | "再记一条（第 N 条）" / "查看清单" / "回到首页" |
| 详情页 | 按条目分段展示，每段标题"第 N 条"，各自带"编辑这条 / 删除这条"；底部"这天再记一条" |
| 月历 | 圆点下方显示当天条数角标（>1 时） |
| **清单** | 按日期倒序分组，逐条列出：序号 + 标题（取①栏，缺失回退①-A）+ 元信息（写了几栏 / 情绪标签 / 草稿标记） |

> **为什么取消上限**：3 条是上一轮我自行加的约束，书中并无此限制。"不催促、不评判"的原则也要求产品不去规定"今天写得够多了"——写多少由用户自己定。

**填写规则**：

- **必填 3 栏**：① / ② / ①-A。三栏有内容即可保存，其余五栏留空不阻碍。
- **沉浸处理**：聚焦某一栏时，其余栏降至 40% 透明度，减轻视觉与心理负担。
- **草稿机制**：输入即存（防抖），中途离开不丢失、不弹提示、不提示失败。
- **空栏不展示**：详情页/回看时空栏整块不渲染，避免"这里没填"的隐性指责。

### 4.3 F3 即时正反馈（留存关键）

保存成功后立即展示发现卡，这是新手期"第一个看见自己的正反馈"。

**提取规则（三级回退，绝不编造）**：

1. 优先取 **①-B 对自己的新发现** → "我发现了：…"
2. ①-B 为空 → 取 **①-A 重新注意到了什么** → "我重新注意到：…"
3. 两者皆空 → 中性兜底"你记录下了今天"，**不生成任何用户没写过的洞察**

**其余元素**：

- **情绪关键词条**：若②栏点选过情绪标签，以暖琥珀色细条呈现；无标签则整条隐藏（不强行填充）。
- **鼓励语**：一句温和肯定（如"又多看见了自己一点"），配轻微上浮动效。

> 【原文边界】正反馈**不是强行正能量、不是否认痛苦**。用户写"我很难过"，产品绝不会改写成"这是成长的契机"。虚假正反馈会摧毁"发现式复盘"的信任基础——宁可反馈平淡，不可编造洞察。

### 4.4 F4 日历回看

- **月历网格**：有记录的日期填充主色圆点，内容越充实色阶越深；**无记录日期留纯空白，不标记缺失、不显示叉号**。
- **本月概览**：显示本月记录天数，语气温和中性（如"这个月，你有 12 天记录了自己"），**不做"缺了几天"的对比**。
- **月份切换**：左右箭头切换，不可切换到未来月份。
- **点击行为**：有记录 → 进单日详情；无记录 → 为该日补记；未来日期不可点。

## 4.6 设计系统（v1.3 重做）

### 设计原则

| # | 原则 | 说明 |
|---|---|---|
| 1 | **克制优先** | 不用渐变炫技、不用彩色背景块。暖纸底色 + 大量留白，让用户的文字成为页面唯一的"颜色" |
| 2 | **层级靠对比而非装饰** | 信息层级由字号、字重、中性色明度建立，而非靠边框、阴影、色块堆砌 |
| 3 | **一个强调色** | 全站仅深青绿一个主色 + 低饱和琥珀一个点缀色。主色只用于"可行动"，点缀色只用于"发现/收获" |
| 4 | **动效服务于理解** | 动效只做两件事：表明从哪来（位移渐显）、表明可点击（hover 反馈）。时长 0.22-0.5s，统一缓动曲线 |
| 5 | **无障碍是底线** | 正文对比度 ≥4.5:1；`:focus-visible` 键盘焦点环；尊重 `prefers-reduced-motion` |
| 6 | **暗色不是反色** | 暗色独立调中性色阶与阴影，不做简单反转（纯反转会让阴影失效、对比度失衡） |

### 令牌体系

| 类别 | 令牌 | 说明 |
|---|---|---|
| 中性色阶 | `--ink-900` → `--ink-200` | 9 级中性，取代原先笼统的 text/sub2/muted 三色 |
| 纸面 | `--paper` / `--paper-2` / `--paper-3` / `--surface` | 背景、次级背景、三级背景、卡片面 |
| 主色 | `--pri` / `--pri-600` / `--pri-400` / `--pri-050` | 默认态 / hover 态 / 边框态 / 浅底态 |
| 点缀色 | `--acc` `#A08D4E`（苔原枯草金） | **09-03 定稿为"山谷苔原·沉静"**：浅色主色`#45594B`、点缀`#A08D4E`；深色主色`#8FAB98`、点缀`#C0AD66`。中性色阶掺冷绿调，卡片纸底带雾感。详见《配色方案对比_0903.md》 |
| 圆角 | `--r-xs` 8 → `--r-lg` 24 | 5 级，卡片用 18、按钮用 999、输入用 10 |
| 间距 | `--sp-1` 4 → `--sp-7` 48 | **8px 基准网格**，杜绝随意的 13px/22px |
| 字号 | `--fs-xs` 12 → `--fs-2xl` | 标题用 `clamp()` 做流体字号，小屏自动收窄 |
| 阴影 | `--shadow-xs` → `--shadow-lg` | 4 级，均带极低透明度，模拟纸面浮起而非"投影盒" |
| 缓动 | `--ease` `cubic-bezier(.22,.9,.3,1)` | 全站统一，避免各处动效节奏不一致 |

### 关键改进点

| 项 | v1.2 | v1.3 |
|---|---|---|
| 色彩 | 6 个松散变量，暗色为简单反转 | 中性 9 级 + 主色 4 阶 + 点缀 2 阶；暗色独立调校 |
| 间距 | 硬编码（16px/18px/22px 混用） | 8px 网格令牌化 |
| 字号 | 固定 px | 标题 `clamp()` 流体，随视口平滑缩放 |
| 阴影 | 2 级、偏重 | 4 级、轻量化，卡片默认仅 `--shadow-xs`（hover 才升到 md） |
| 正文宽度 | 全局 1120px | 阅读页 760px（约 42 字/行，最佳阅读宽度），记录页两栏保持宽屏 |
| 焦点 | 无键盘焦点样式 | `:focus-visible` 焦点环 |
| 降级 | 无 | `prefers-reduced-motion` 关闭动效 |
| 细节 | 无 | 桌面端自定义滚动条、`font-feature-settings` 字距优化 |

> **旧令牌兼容**：保留 `--bg` / `--card` / `--sub` / `--text` / `--muted` 等旧变量名，统一指向新令牌（别名桥接），确保历史样式引用不会失效。

## 5. 核心业务流程

```
【每日】打开网页 → 八栏引导填写（左=记录 / 右=意义重塑）
   ↓ 输入即存草稿
【保存】三栏必填校验 → 即时正反馈（我发现了…）
   ↓ 写入 localStorage → 若开启云同步则 PUT 回推 GitHub
【回看】日历视图 → 色阶密度 → 单日详情（查看/编辑/删除）
   ↓
【备份】设置页 JSON 导出/导入 + GitHub 同步配置
```

数据流闭环（第一期）：**记录 → 即时发现 → 沉淀存储 → 可视化回看 → 再次记录**

> 完整的"记录→筛选→关联→提炼→行动"闭环需周/月复盘支撑，属第二期，见 §7。
> **注**：八栏本身已内嵌一个微闭环——①-A（理解本质）→ ②（新行动）→ ③（预期结果），这正是科瑟根 ALACT 模型的落地。
